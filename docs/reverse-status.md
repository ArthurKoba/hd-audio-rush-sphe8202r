# Reverse status

Last synchronized from the initial investigation and current Ghidra/STK results.

## Confirmed

### Board / storage
- Physical board silkscreen: `SPHE8202RD_SPDIF_V02`.
- Main Sunplus package marking: `SPHE8202R`.
- External NOR marking: `P25D80SH`.
- Stock SPI image size: 1,048,576 bytes.
- Stock dump SHA-256: `67d8301f043ecc4d725ec09e38f3c53dd7e71ec26192775811a6a05dd13b545e`.

### Sunplus container
- Sunplus STK opens and unpacks the stock image successfully.
- STK reports firmware version `02R-D-02`.
- STK reports `ROM required: 1M`.
- STK exposes 18 module slots.
- Extracted module corpus is recorded in `docs/firmware.md`.

### Main application ISA
- `ap1.bin`, `cdrom.bin`, `drv_other.bin`, and `wma.bin` contain coherent MIPS32 little-endian code.
- Ghidra import of `ap1.bin` as `MIPS:LE:32:default` is coherent.
- `ap1.bin` image base `0x8067B000` is supported by internal absolute references.
- After rebasing/analyzing `ap1.bin`, Ghidra identifies thousands of functions.

### Firmware feature anchors
The application image contains strings for S/PDIF OFF/RAW/PCM, S/PDIF input, AC3, DTS, PCM, USB, SD and audio setup/output modes.

### Secondary firmware evidence
A captured UART boot log contains:
- `AC695N_soundbox_sdk_release_3.1.0_LineIn_IIS`
- platform path containing `board/br23/board_ac695x_demo`
- `jl_soundbox_lihui`
- `audio_dec_init`
- `spdif_dec_start`
- volume configuration and `VOL_SAVE`

This confirms that AC695N/BR23 software is present somewhere in the running system. The exact physical UART ownership/routing is not yet proven by continuity measurements.

## Likely / provisional

- Secondary marked chip `AK24BP24230` is a JieLi/JL-family audio controller associated with the observed AC695N/BR23 firmware.
- `wma.bin` load base is approximately `0x8073F000`.
- `cdrom.bin` load base is approximately `0x80754000`.
- `drv_other.bin` load base is approximately `0x80782000`.
- `iop.bin`, `iop_rst.bin` and `srvdsp.bin` are microcode/specialized coprocessor images rather than normal MIPS application modules.

## Unknown

- Exact audio signal path from TOSLINK/coax input to the six analog outputs.
- Whether the six analog channels are generated by the SPHE internal DAC, an external DAC, or a mixed architecture.
- Exact control/data interface between SPHE8202R and the secondary controller.
- Whether the board's four USB-like pads implement SPHE USB host only, can be switched to device mode, or expose another service function.
- Exact public part number represented by the secondary marking `AK24BP24230`.
- Exact meaning/unit of STK's `SDRAM 32M` field until the physical SDRAM part is identified.
- Whether stock or modified firmware can expose USB Audio Class device functionality.

## Contradictions

### SPHE8202R vs SPHE8203R
- Physical package marking: `SPHE8202R`.
- STK profile reports: `SPHE8203R`.

Do not resolve this by assumption. Possible explanations include common 8202R/8203R container/profile compatibility or STK profile behavior. Target hardware marking remains authoritative for physical identity until firmware/platform evidence explains the mismatch.

### SCORE7 vs MIPS
Early flat-image probing suggested SCORE7 as a possible Sunplus ISA and a SCORE7 Ghidra backend was validated. After correct STK unpacking, the main application modules disassemble coherently as MIPS32 LE. Current evidence therefore assigns MIPS32 LE to the main application modules. SCORE7 is not the active assumption for `ap1/cdrom/drv_other/wma`.
