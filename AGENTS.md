## Текущая цель

**Только полное восстановление аппаратного поведения из сохранённой штатной прошивки.** Конечный продукт — **собственная прошивка аудиопроцессора**. Исследовать аппаратные блоки SPHE8202R, DSP, IOP и взаимодействие с JieLi; разрешено зайти в код любого прикладного модуля ради доказательства аппаратного вызова, но **не восстанавливать UI, видео, DVD/CD-код ради них самих**. Подробные границы — docs/RECONSTRUCTION_SCOPE.md.

**Не писать заменяющую прошивку, не делать product build, flash, новые API, транспортные реализации или аппаратные эксперименты** до отдельного распоряжения. Исходные дампы/модули оставлять неизменными.

**Git commit, push, PR, merge и переписывание истории запрещены в обычном цикле анализа.** Разрешены только по **новому явному распоряжению пользователя о фиксации конкретного результата**. Даже разовая текущая синхронизация правил не даёт разрешения на последующие коммиты. При разрешении использовать Writer (koba-ai-agent) → PR → независимый Reviewer (koba-ai-reviewer) → merge в main; writer не меняет main напрямую.

**Метрики:** только доказанная полнота восстановления аппаратного поведения по корпусу от 0 до 100%; не количество названий, коммитов, строк текста, инструкции DSP и не board-acceptance. Статическое доказательство, наблюдение исполнения, испытание на плате и product-ready — разные состояния.

## Практика анализа и семантической разметки

- Каноническая семантическая база: Analysis project **sphe8202r_decoder_p25d80** по адресу /projects/sphe8202r_decoder_p25d80.gpr. Сохранять смысловые имена действий, MMIO, глобальных указателей, констант, типов, комментариев. Не утверждать, что новые названия сохранены, пока операция/сохранение не подтверждены.
- Основной Sunplus CPU — MIPS32 little-endian; глобальная база GP = 0x80002B00; доказанная системная MMIO-база S6 = 0xBFFE8000. Не использовать голые указатели в отчёте без назначения и уверенности.
- Уровни: **ПОДТВЕРЖДЕНО / ВЕРОЯТНО / НЕИЗВЕСТНО / ПРОТИВОРЕЧИЕ**. CPU-копирование не является автономным DMA; наличие функции интерфейса в прошивке не доказывает разводку.
- Цикл: новая аппаратная гипотеза → ограниченная control/data-flow трасса → доказательство по инструкциям/P-code → осмысленная разметка → следующий аппаратный пробел. Не повторять установленное ради процента. При тупике переключить направление.
- Работа через узкие MCP-проходы и при необходимости скрипты; не создавать скрипт просто ради скрипта. При занятой очереди Analysis не выдавать внешнюю документацию за сохранённые символы.
- Содержимое другой ветки/локального workspace не является текущим main; принимать данные после сравнения авторитетных источников.
