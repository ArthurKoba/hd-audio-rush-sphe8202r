## Источники истины и аппаратная область

- GitHub main — цели, границы, правила, общая карта устройства. **Issue #43** — актуальное управление задачами, оценки 0–100%, чек-лист и блокировки.
- Канонический Analysis-проект sphe8202r_decoder_p25d80 — **единственная техническая база** регистров, функций, указателей, алгоритмов, гипотез, трасс и доказательств. Новые находки осмысленно именовать/комментировать в Analysis и сохранять. Не объявлять сохранение без подтверждения.
- Основной процессор SPHE8202R (MIPS32 LE); аудио DSP и служебный IOP — **отдельные архитектурные блоки**. JieLi — **закрытая внешняя микросхема**: не искать/не изучать её собственную прошивку. Все обнаруженные в SPHE потенциальные каналы взаимодействия с JieLi исследовать полностью.
- Состояния: ПОДТВЕРЖДЕНО / ВЕРОЯТНО / НЕИЗВЕСТНО / ПРОТИВОРЕЧИЕ. Наличие интерфейса в коде не является доказательством физической разводки, CPU-копирование не является автономным DMA.

## Процесс и запреты

Текущий этап — **только анализ полной аппаратной части и всего аудиопайплайна, USB и UART до 100% по штатной прошивке**. Приоритет: самые слабо исследованные полезные блоки и неизвестные MMIO. Можно смотреть UI/видео/DVD/CD только до границы аппаратного доказательства; не анализировать их прикладную логику ради самой логики.

0% — направление не исследовалось, 100% — восстановлено доступное по исходной прошивке аппаратное и аудиоповедение. Тесты на плате и реализация — следующий этап. Не подменять прогресс повторными проверками.

**Без отдельного явного разрешения пользователя на конкретную фиксацию не создавать Git commits, push, PR, merge.** При разрешении: Writer → PR → независимый Reviewer → main. В обычном цикле: техническая разметка в Analysis; управление задачами — в Issue #43. Не писать продуктовые прошивки/API и не изменять исходные бинарники.
