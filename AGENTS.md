## Карта остальных материалов — не обязательны автоматически

- README.md — продукт, общие аппаратные домены и исходный корпус.
- docs/analyze-status.md, docs/firmware.md, docs/hardware.md, evidence/ — исторические свидетельства для **проверки переноса в Analysis**. Не действующий источник технической истины; не дополнять в ходе обычного исследования.
- analysis/modules.csv — карта модулей; firmware/ — неизменяемый исходный дамп/бинарники; tools/ — инструменты исследования и старые эксперименты.
- Библиотека ai-agent-workflow — подробные правила трассировки, evidence, жизненного цикла Analysis и отчётности, открывать профильный модуль по необходимости.

## Источники истины и аппаратная область

- GitHub `main` — цели, границы, правила, общая карта устройства **и подтверждённые переиспользуемые артефакты** (инструменты, точные константы/интерфейсы, тесты). **Issue #43** — основная задача, общие оценки 0–100%, чек-лист и блокировки. Связанные Issues (в том числе **#48 — USB/Wi-Fi/Bluetooth**) — исследовательские ветки и детальные открытые вопросы. Не копировать в репозиторий журналы прогресса из Issues.
- Канонический Analysis-проект sphe8202r_decoder_p25d80 — **единственная техническая база** регистров, функций, указателей, алгоритмов, гипотез, трасс и доказательств. Новые находки осмысленно именовать/комментировать в Analysis и сохранять. Не объявлять сохранение без подтверждения.
- Основной процессор SPHE8202R (MIPS32 LE); аудио DSP и служебный IOP — **отдельные архитектурные блоки**. JieLi — **закрытая внешняя микросхема**: не искать/не изучать её собственную прошивку. Все обнаруженные в SPHE потенциальные каналы взаимодействия с JieLi исследовать полностью.
- Состояния: ПОДТВЕРЖДЕНО / ВЕРОЯТНО / НЕИЗВЕСТНО / ПРОТИВОРЕЧИЕ. Наличие интерфейса в коде не является доказательством физической разводки, CPU-копирование не является автономным DMA.

## Процесс и запреты

Текущий этап — **анализ аппаратуры, аудиопайплайна, USB и UART по штатной прошивке**, без сборки собственной прошивки. Активная профильная задача [#48](https://github.com/ArthurKoba/hd-audio-rush-sphe8202r/issues/48) — полное восстановление USB Host для прямого Wi-Fi/Bluetooth-радиомодуля. Допустима предварительная подготовка C/C++ драйверных интерфейсов и тестов, подтверждённых анализом; не выдавать их за проверенный на плате код. Можно смотреть UI/видео/DVD/CD только до границы аппаратного доказательства; не анализировать их прикладную логику ради самой логики.

0% — направление не исследовалось, 100% — восстановлено доступное по исходной прошивке аппаратное и аудиоповедение. Тесты на плате и реализация — следующий этап. Не подменять прогресс повторными проверками.

**Разрешение владельца проекта от 15.10.2026:** можно делать **прямые атомарные коммиты в `main`** для доказанных, проверенных и реально повторно используемых улучшений проекта без нового разрешения на каждый такой коммит. Держать изменения узкими, проверять их до публикации, указывать относящийся Issue и сообщать SHA/результат после публикации. Для этих изменений PR и Reviewer необязательны; для сложных или рискованных изменений их можно использовать как дополнительную проверку. **Это разрешение на фиксацию состояния репозитория, не разрешение на прошивку платы или разработку нового firmware вне текущего этапа.** Техническую семантику фиксировать в каноническом Analysis; ход исследования, гипотезы, задачи и проценты — в Issues (основной #43, профильные связанные). Не создавать параллельные локальные отчёты сравнений. Не изменять оригинальные бинарники, образ SPI Flash или каноническую базу без отдельного относящегося к ним основания.
